# WishOS 系统层次与应用自由度

当前实现见[运行时](../../../docs/agent-os-runtime.md)，下述边界适用于生成应用和移植设备。

## 三类约束

1. 硬件事实：可用引脚、电压/电源拓扑、总线时序、显示完成信号、音频格式、芯片无线能力。属于原生适配器，应用不能覆盖。
2. 系统机制：执行预算、应用生命周期、资源租约、异步回执、呈现顺序、配置事务和恢复入口。系统保证正确性；具体配额来自设备默认值或系统配置。
3. 应用策略：页面、导航、按钮含义、显示 profile 选择、语音交互、定时任务、离线行为。全部由普通运行时包实现，工厂套装也是同一层的可替换应用。

不要把一块板的 RAM、引脚、刷新时间、颜色或默认 SSID 写成通用 OS 规则。不要为某个应用页面增加内核分支；必要的驱动/服务协调可以直接耦合。

## 构建与存储

平台包选择芯片/SDK；可复用驱动提供能力；设备包组合接线、生命周期、资源默认值、分区与初始套装。原生变更编译，应用文件在线加载。普通用户取得默认完整设备固件，不负责选装协议或模型。

Flash 最低 4 MiB。代码分区由设备包预算，构建工具校验物理容量和实际镜像。应用/UI 位于可管理的文件系统目录，初始 LittleFS 镜像只用于首次部署。8/16 MiB 可以增加代码预算或可写文件空间，是否允许用户应用落内部 Flash 是设备配置，不依赖芯片名称猜测。

存在多个应用和版本时，先准备新版本目录并校验，最后切换应用索引；不要原地覆盖执行/呈现中的资源。Launcher、语音、手机传图均为普通应用。系统独立输入路径保证可返回/发起新请求，具体按键绑定和指导文字留在配置/应用中。

## 调用全路径

生成程序前发现能力与 schema，再配置并验证整个变更。异步操作使用完成回调/保留回执，不能把 accepted 当成完成。应用回调只在系统事件循环，阻塞 SDK 操作在原生工作器。

应用退出必须释放其 VM、回调、定时器、文件和服务租约；不能撤回的 BUSY/DMA 操作结束后释放。后台工作器有独立执行和内存预算，不开放原生任务优先级、寄存器或直接总线。

## 交互和呈现

UI 绘制属于系统服务，页面定义属于应用。内容更新与前台导航分开，统一呈现管理器维护可见/期望状态。应用选择发现的显示 profile；新 LCD/OLED/点阵/EPD 由驱动说明能力和完成依据，不要求通用内核理解其波形。

刷新期间仍可采集按钮/IMU/录音；如何派发输入由策略配置。不得为了立即响应而打断已提交的 EPD 刷新。共享 SPI 只在事务期间占用，等待器件内部操作不占总线。

## 文件、录音与重处理

文件位置和容量以 VFS 发现为准，遍历分页；发现不创建目录、不写卡、不做完整扫描。卷准备与协议探测分离。读失败不能伪装成 EOF/空目录。小说等重资源及随机访问索引由上位端生成，设备按偏移读取。

录音用独立可解码压缩块；无卡只保留短 RAM 缓冲并报告丢块。是否保存、重试、保留历史和淘汰规则均可配置，不能暗中回退到内部 Flash。

网络/AI 调用由系统服务提供。轻量确定性工作本地执行；重图像、页面提炼或模型任务由显式远端动作完成。MCP/Harness 和服务端 session 不进入原生硬件驱动。返回动作只有 system/application 两种，可任意有序交替；系统变更完成与应用回复分开。

## 移植与验证

新设备不必编辑可移植内核。同一 MCU 可有不同显示、输入、编解码器、PSRAM/Flash 和存储布局。驱动只声明已实现能力；没有适配器的功能不静默接受配置。主机契约测试、SDK 编译、实物运行和显示光学效果分别验收。
