# Notes OS：可移植系统契约

实施更新：2026-10-12，已有可编译的资源/策略/VFS、LVGL JSON 子集与 Lua 运行时。下文同时包含扩展目标；当前准确能力与尚未实现项见仓库 `docs/agent-os-runtime.md` 和 [动态 UI 指南](dynamic-ui.md)。


2026-10-12；公开系统的目标设计。本文替代此前把应用行为写进驱动的设计。
这是设计与选型状态，不是固件已实现能力声明。调用前必须读取设备的实时目录、版本、限制和生效配置。

## 1. 层次与职责

| 层 | 负责什么 | 可以怎么改变 |
|---|---|---|
| BSP / 硬件驱动 | 引脚、总线拓扑、供电依赖、DMA、时序、BUSY、支持格式、物理范围 | 移植/编译对应硬件；应用不能改写硬件事实 |
| 系统机制 | 资源所有权、任务、事件、总线调度、VFS、内存预算、网络连接、状态查询、配置事务 | 稳定接口；实现可替换，扩展通过注册加入 |
| 策略 | 事件响应、排队、按键映射、录音停止条件、储存、重试、功耗与显示选择 | 系统、应用、会话或单次调用动态配置 |
| 应用 / UI | 页面、路由、按钮语义、条件动作、数据与网络操作 | 从文件加载、热更新、选择运行时；依赖抽象能力而非某颗MCU |
| Harness / Agent | 理解用户、调用已有工具、生成应用/资源、协调任务 | 通过系统能力与状态接口调用；不承担毫秒级硬件调度 |

移植到 LCD/OLED 或其它 MCU 后，替换底层驱动和可用能力集合，上层继续使用显示、音频、网络、输入、文件、事件、作业与配置接口。
系统可以约定基础设备要求，但不把所有未来扩展限制在固定的能力类型枚举里。

### 三类规则必须明确区分

1. **硬件事实/硬约束**：来自驱动、器件与接线。例如指定显示器忙时不能发送命令；共享电源轨不能独立关闭其中一支；采样率只有若干可用值。这些字段只读，携带来源。
2. **系统正确性不变量**：不得使用已释放资源，不得越过实际内存，不得把 accepted 报成 completed；同一事务的数据和回执身份一致；配置失败不得留下半生效状态。这些不能被策略绕过。
3. **可变策略**：是否响应按钮、何时刷新、录音多久、是否保存、使用哪个网络、应用如何返回等。系统只提供机制、可用范围和默认配置，用户/Agent 可以更改。

“默认值”“当前构建上限”“物理限制”必须分开。更大队列可能需要重新分配内存；如果预算不足，报告 required/available/conflict，而不是偷偷钳制成另一行为。

## 2. 硬件基线与能力发现

基础产品要求：至少一种可用网络连接、一块显示器、一个音频输入、一个按钮，以及满足该发行构建预算的 RAM 和 Flash。
网络可以是 Wi-Fi、以太网或蜂窝；显示可以是电子纸、LCD、OLED；不要求 IMU、LP 核、三个按钮、USB OTG 或某个 SPI 控制器。

| 参考级别 | 内存/存储方向 | 定位 |
|---|---|---|
| 推荐起点 | C6 等级，512KiB 级片上SRAM、4MiB或更多Flash | 完整基础系统的验收目标 |
| 精简起点 | C3 等级，400KiB标称SRAM（含cache占用）、4MiB或更多Flash | 通过裁剪与并发预算评估后支持；不是保证所有服务同时开启 |
| 扩展储存 | 推荐可拔 microSD/TF，也可为其它块设备或远程卷 | 大资源、字体、书籍、录音历史与持久重传 |
| 无扩展储存 | 内置系统资源、网络流、有限RAM缓存仍可用 | 大型离线功能按实际空间/能力降级 |

这些数字是产品目标，不是已经跑过全部服务的最低资源证明；还必须验收联网后的空闲heap、最大连续块、任务栈、渲染与音频并发余量。
512/400KiB也不等于全部可分配给应用。C3/C6原生USB是固定Serial/JTAG功能，换成有OTG的平台才可能增加USB存储类接口。

每个资源自描述：稳定实例ID、接口版本、方法的输入/输出schema、事件、只读facts、可改settings、limits、依赖、成本、可用状态与使用说明。
例如应用寻找默认 `display` 或 `audio-input` 实例，而不是寻找“E6”“GPIO22”“第三个按钮”。这是常用接口族，不封闭其它扩展注册。
按钮数量与ID从目录读取；A/B/C只属于某块板的别名。逻辑动作如 back/next/talk 可以映射到一键长短按、多键或其它输入。
Wi-Fi发射功率是某个网络适配器的扩展项；通用联网接口仍提供 connected/link/route/connect/disconnect，无线制式变更不要求重写应用。

## 3. 配置是一套系统接口

目标服务提供 describe、read、validate、apply、reset、subscribe。具体资源可扩展其方法，统一服务负责配置的版本和作用域。

每个可配字段返回：类型、单位、合法范围、当前值、来源、默认值、可否持久化、何时生效、与哪些资源冲突。
配置来源：发行默认 → 用户系统配置 → 应用/会话配置 → 单次调用覆盖；权限与适用范围按资源声明。硬约束不参与覆盖。
应用可读取最终 effective 值及其来源，不能只看到自己提交的 requested 值。

`validate` 返回计划与资源需求；`apply` 带 expected_revision 与作用域，返回 applied/rejected/deferred、实际配置和原因。
需要等显示ready、停采样或重新挂载才能应用的更改，必须明确 deferred 与生效条件；事件到达后再回报 applied。
跨多个资源的变更先验证，再在共同安全边界提交；不能一半改了采样率、一半仍按旧编码读流。
持久化是显式选项，RAM临时配置不自动写Flash；支持重启恢复的存储后端与恢复结果可查询。

### 应当开放的策略示例

| 领域 | 可配置项（须由当前实现发现其支持范围） |
|---|---|
| 输入 | 采集/订阅开关、去抖、长按/连击、自动重复、绑定、优先级、广播/消费、刷新中 dispatch/queue/coalesce/drop |
| 页面输入目标 | 实际呈现页、期望页、指定会话、绑定捕获者；按下与松开的关联规则 |
| 显示调度 | 排队或拒绝、FIFO/latest/coalesce、合并期限、优先级、节流、去重/force、驱动别名、降级策略 |
| 录音 | 手动/按住/切换/定时/事件触发、设备支持的格式、采样率、时长/字节上限、预录、分段、缓存与落盘、历史、重试、缺块容忍、满卡/断网策略 |
| 网络 | 连接方式、主动/被动服务、重连、超时、限速、费用/省电偏好；适配器可用的专有参数 |
| 调度 | 队列预算、任务预算、总线权重、期限、块大小、并发度、优先级与回压策略 |
| 功耗 | 空闲超时、休眠类型、唤醒源、低电量处理、关闭前事务如何结束、网络在线租约 |
| 文件/字体/UI | 挂载、缓存、配额、保留期、导出协议、字体回退、页面更新/返回策略、应用作用域 |

模式列表由策略处理器注册，可扩展；不能把表中示例当成永远封闭的系统枚举。
“五分钟”“B键说话”“刷新中立即响应”“新画面覆盖旧画面”“默认保留历史”都只能是某份可编辑配置。
录音时长可按配置为有限值或无用户时限；后者仍受到储存空间、供电和当前驱动能力约束。当前驱动不支持时必须如实报告，不能声称已解除限制。

## 4. 状态感知和资源预算

Agent与本地程序通过同一状态服务读取、订阅和设置条件触发。每个样本带时间、采样窗口、有效性与来源；不可测字段返回unknown/null及原因。

| 资源 | 最低应提供的观测 |
|---|---|
| 内存 | 总量/当前空闲、最低空闲、最大连续块、池占用、预留、分配失败、外部RAM状态 |
| CPU/任务 | 各核统计窗口内利用率、时钟、任务运行时间/栈高水位、超期计数；不可用时不以主频冒充占用率 |
| Flash | 芯片/分区大小、系统占用、可写卷可用空间；程序分区空白不冒充应用可写空间 |
| 文件卷 | 格式、总/可用/预留容量、挂载/可写、是否可移除、I/O错误、忙状态、数据刷新状态 |
| 显示 | 所选驱动/色表、ready/busy/fault、队列、当前与期望呈现身份、已观测时长 |
| 录音 | 采样参数、持续时间、数据量、缓冲高水位、缺失样本、落盘/上传进度、当前策略 |
| 网络 | 接口、路由、连接、吞吐、延迟/丢包的观测、重试队列；信号与流量费用为可选能力 |
| 电源 | 可测电压/电量、功耗模式、活动租约、阻止睡眠的原因、可用唤醒能力 |

状态查询不能触发一次全卡扫描堵住系统。慢指标后台计算、缓存，返回 freshness；指标采样频率与开销预算可配置。
任务提交可先作资源预估/预留；发生竞争时由策略决定排队、退让或拒绝，结果带原因。系统必须始终保留基本控制、错误回报与资源回收所需的预算。

## 5. 显示：内容驱动与硬件ready边界

对外公布显示驱动身份、可用颜色/色彩空间、实际或估计呈现速度、输入格式、尺寸方向、更新范围、维护和资源要求，以及推荐用途。
速度是能力描述；波形阶段、原始电压、PLL或内部试验指令不属于产品API。显示驱动源码与正常实现属于开源产品，不等于附带内部试验入口。
同一色彩空间可以有多个性能/品质不同的驱动。UI可以自由选择可用驱动，或使用可编辑的用途别名。推荐是建议，不是强制“图片只能某驱动”。
LCD/OLED可以报告连续色域/像素格式和刷新能力，调色板电子纸报告离散色表；不得要求所有显示器实现六色表。

**当前电子纸硬约束：刷新期间不允许发任何新的屏幕命令，必须等BUSY进入驱动定义的ready状态，并满足规定的稳定时间。**
这包括新帧数据、刷新、清屏、关断指令、配置改变和复位；应用不能用force或高优先级绕过。
BUSY信号由驱动读取，不必通过屏幕SPI命令查询。超时产生fault，不等价于ready；不能超时后自动发送复位或下一条命令。异常恢复必须由明确的驱动恢复条件决定。
新请求可被系统接受、排队、合并或拒绝，但接受请求不代表已对屏幕下发。实际执行始终经过同一ready门控。
其它显示器使用DMA完成、fence或硬件就绪条件实现同一抽象，不强制存在名为BUSY的引脚。

显示应用状态、数据传输完成、物理呈现完成分别回报。取消未执行作业是队列机制；已启动呈现能否取消由驱动声明，当前电子纸为不能。
刷新期间输入如何处理由配置决定：立即dispatch、仅暂存、合并、忽略，或按事件分别设置；网络请求/语音/IMU同样按所属策略处理。
输入采集与事件派发分开：禁用普通页面响应不意味着停止必要的驱动完成信号和系统控制服务。
按住录音是一个可选绑定方案；其press/release关联由动作实例管理。选择它时必须正确收尾，不能切页后释放错对象。切换式或定时式录音不强制在release停止。

哈希去重包含实际内容、显示驱动/色表版本和几何变换。重启后显示状态的可信程度由驱动持久状态机制说明，不能仅因SD有旧图就声称已显示。
维护期限、停机清白等只属于适用显示驱动/板型的约束或建议，并区分两者；不能把电子纸的24小时维护和白屏动作写成LCD/OLED通用规则。

## 6. SPI与电源由系统按事务调度

屏幕与SD分时使用同一SPI，分别使用自己的片选与总线参数。屏幕显色时保持其片选未选中并释放SPI，调度器可服务SD；显示状态所有权仍保留。

总线时钟属于物理适配器配置。已知型号的屏幕使用驱动默认时钟或系统指定值，不自行扫描。可换卡的 SD 用卡寄存器与协议状态进行内容无关的链路握手；文件系统挂载另行执行。时钟候选由主控可达档位、卡当前协议模式、系统配置共同决定，超规格实验需要显式声明，且寄存器应答不冒充文件读写长期可靠性。固定值不通过链路握手时仅该存储设备不可用，系统其它能力继续运行。未来接入新外设时增加其驱动与端点配置，不让应用、VFS或UI依赖某块板的GPIO和具体时钟。

- 总线锁：覆盖不可拆开的单次事务或驱动声明的最小原子块。
- 设备状态锁：覆盖整次显示操作，防止另一个调用者同时修改该屏幕状态。
- 电源租约：覆盖设备实际仍需供电的区间，遵守共享轨的真实连接关系。

等待BUSY不得占着SPI锁；SD交易不是发送给屏幕的命令。只有访问屏幕本身的事务需要通过屏幕ready门控。
调度器在允许的边界切换设备；不得在一次不可中断的电气事务里交叉字节，也不能在总线仍忙时变频/切换模式。
块大小、权重、优先级、期限和并发策略可改，硬件原子边界不可改。输入/音频采集采用独立任务/DMA；总线操作不能持有全局应用锁。
最坏服务间隔、队列等待和SD写入长尾须可观测。总线足够快不等于任何SD卡都无写入停顿，预算不足时按配置回压或报告失败。
若某BSP确有共享线/供电导致不能并发，应以约束声明反馈；不能把某块板的耦合写成整个OS的恒定假设。

## 7. 录音是可配置流服务

采集服务提供会话、流、格式、起止、分段与样本位置；网络、RAM与文件是独立可选sink，可同时连接。
采集任务只交付有界块，不等待网络ACK或同步FAT操作。块由缓冲池管理，每个sink有自己的进度与回压；网络读取不能消费掉历史落盘需要的数据。

可配置：触发方式、采样参数、最大时间/字节数、预录缓存（支持时）、内存预算、块长、目的地、编码、历史策略、重传、保留/删除、断网/满卡/失败行为、允许缺失范围。
默认策略与内置应用一起提供，可替换。不能在系统层规定所有录音必须五分钟、必须16kHz、必须上传、必须保存或必须按住。

16kHz、16bit、单声道PCM为32,000B/s，五分钟为9.6MB，仅用于容量规划。可持续流式或落卡，不要求整段进入内存。
重传用稳定的录音与块身份、校验、接收游标；ACK区分网络接收与可靠储存。相同录音不能因重连被Harness执行两次。
采集、保存、上传、识别、任务投递、结果显示分别有状态。是否补静音、容忍多少缺口以及是否按顺序steer由策略/应用决定；报告真实缺口是系统不变量。
有卡可配置可靠重传与历史；无卡时按可用RAM和网络能力报告支持范围。应用可拒绝启动需要持久缓存的模式，也可显式允许降级。
正常关闭/休眠与活动流的关系可配置为等待、停止并提交、暂停（若支持）或拒绝；不能在未允许的数据损失下切断正在写入的卷。

## 8. VFS、exFAT与快速定位

OS公开VFS文件接口，应用不依赖FAT32、SD、Arduino SD类或某种存储介质。存储驱动负责实现open/read/write/seek/stat/list/flush与能力差异。
默认卷别名如 `/storage/user` 可以指向TF卡、其它块设备或受支持的远程卷；实际挂载表可查询。不将缺卡时的大型资源无声写进内部Flash。

**目标支持exFAT与FAT32，按卡上既有格式挂载，不要求用户重格式化为FAT32。**
支持的格式、64位偏移、最大文件、文件名编码、大小写语义、持久化保证都由卷报告。
当前Arduino工具链FatFs的`FF_FS_EXFAT=0`是构建选择；通用FatFs本身支持exFAT，Arduino生态也有SdFat 2的FAT/exFAT实现。
Arduino路线优先评估SdFat 2后端；ESP-IDF路线可采用配置完整、版本一致的FatFs。选择一个后端挂载同一张卡，不让两个文件系统栈并发管理同一卷。
exFAT的较大文件、连续分配及分配位图对大资源有帮助，但它没有自动生成章节索引，也不等于日志文件系统/任意掉电安全。
本地与协议的offset/length采用64位；经过JSON时用十进制字符串或明确的64位编码，避免JS超过2^53后精度丢失。

### 书籍与内容索引

**设备导入时不建立全书索引，不进行同步全文解析。索引由Agent调用云端/Hub/上位机工具提前生成。**
内容包包含源内容或规范化文本、章节/段落/锚点偏移、可选分页表、资源表、内容hash和生成器版本；设备只做有界验证与按需读取。
大包校验可随传输计算hash，后台完成后提交版本，控制界面保持可操作。缺索引时报告index_missing并请求外部准备，不能擅自在板端开始长扫描。
云端不可用时可选择先打开已具备索引的部分/顺序读取已有格式；是否允许这种功能由应用选择，不声称随机跳转已可用。
页码依赖字体、字号、排版和显示尺寸。若更改后没有匹配分页索引，可按锚点在局部有界重排、请求云端新分页，或暂用旧布局，策略可配置；不得触发板端全书重建。

会话/录音的索引在设备生成数据时随写入增量维护，成本按块摊销；这与导入时扫描一本书不同。云端生成的会话包也可携带索引。
文件位置索引与内容索引分离：簇链/extent定位由FS负责，消息/章节定位由内容格式负责。exFAT连续文件和fast seek只能改善前者。
读取索引采用分页缓存；打开时验证版本，不把整个索引读进RAM。异常恢复默认只检查未提交尾部，若需要更广泛修复则作为可配置后台/外部任务，不能堵住交互。

## 9. NFS与HTTP共享文件

“nsf”按NFS理解。设备导出自身储存给电脑属于NFS server；设备访问NAS属于NFS client，两种能力单独声明。
**NFS不是排除项：规划为可选的NFSv3 over TCP服务，接统一VFS。** 是否能在C3/C6上与全部任务同时开启，需实际内存和并发验收，当前尚未实现。

实现路线：

1. 复用成熟ONC RPC/XDR编解码和NFSv3定义；参考libnfs的RPC服务端基础或UNFS3的服务端行为，替换/实现嵌入式VFS后端。
2. 实现MOUNT v3、按需的rpcbind/portmapper与NFSv3核心操作；TCP record分片有总长上限，不按远端长度无限分配内存。
3. 先验证目录、属性、随机读取和桌面挂载，再实现CREATE/WRITE/COMMIT/RENAME/REMOVE等写操作；只读阶段明确导出ro。
4. FSINFO公布rsize/wsize能力，连接数、块大小与请求并发按预算配置；使用小块流式I/O，不要求整文件进内存。
5. 文件handle使用稳定对象身份与卷generation；不能直接用易变路径或FAT目录偏移冒充持久inode。卡被替换/不再可用时返回STALE，不读取旧对象。
6. 请求重发缓存与文件操作身份配合，避免重复写副作用；FILE_SYNC/COMMIT完成依赖底层同步结果，不能只写入RAM就确认持久。
7. FAT/exFAT没有的硬链接、特殊文件等返回明确不支持；NFS锁服务、完整Unix权限和NFSv4不是首版隐含承诺。

UNFS3是现成用户态服务端，但依赖libtirpc/POSIX，不能直接拿来当Arduino库；libnfs主要是客户端与RPC基础，也不是现成的SD共享服务器。
移植路径成立不等于已有本板可用固件。最低验收要包括macOS/Linux挂载、目录游标、断线重试、重命名、64位offset、卡移除、同步写与音频并发。
手机浏览器仍使用HTTP文件管理器；NFS不能替代网页入口。HTTP与NFS必须共用VFS的文件所有权/修改通知，不能各自绕过缓存和打开文件状态。
NFS客户端长时间持有挂载会影响休眠。服务启用时是否保持在线、空闲退出或允许断连由电源/服务策略决定，应用能查询当前阻止睡眠的租约。

## 10. UI复用已有开源实现

停止把之前自造的`notes-ui/1`节点语言当正式标准；旧草案不在公开契约中继续扩展。
优先复用**ESP-Brookesia JSON UI文档/绑定机制 + LVGL渲染**，只补Notes OS需要的服务桥接、导航语义、策略上下文和显示呈现适配。
这是优先评估路线；必须通过无PSRAM资源验证再确定直接采用哪些组件。

### 已核对的实现与取舍

| 项目 | 能复用什么 | 结论 |
|---|---|---|
| ESP-Brookesia | 后端无关JSON UI、相对资源、条件布局、动作事件、绑定、screenFlow、字体注册、LVGL后端 | 最贴近需求；Apache-2.0。取必要组件，不能整套照搬到无PSRAM板 |
| LVGL核心 | MIT图形库、布局、控件、输入、文件/字体接口、分块渲染与多个显示适配 | 作为渲染层优先候选；物理电子纸刷新在独立呈现层进行 |
| EEZ Studio/Flow | 开源可视化编辑、LVGL支持、流程与行为编排 | 备选作者工具；编辑器与运行时许可/资源分别核对，暂不要求用户必须装编辑器 |
| Slint | 声明式界面、响应式属性、跨平台与行缓冲渲染 | 技术备选；当前无PSRAM完整联网/音频余量与动态加载要求未验证 |
| Nuklear | 轻量C绘图/控件 | 适合轻UI后端，但还缺外部声明式文档、资源与应用生命周期，不能单独解决需求 |

核对的Brookesia源码提交为`e937455b0db1a3e873b1da61d6d13652f3dcc7e2`：GUI接口0.8.2，LVGL后端0.8.5，后端依赖LVGL9.5.0。
其master v0.8要求ESP-IDF6.x；当前Arduino使用IDF5.5系列，不能无检查直接依赖。其默认显示任务栈40KiB、条带20行、示例启用，且有Boost.JSON/容器依赖；这些需要裁剪与测量。
新组件可选择以ESP-IDF为构建底层并保留Arduino组件，或将必要GUI接口适配当前构建；选择依据是构建、内存和稳定性，不为了Arduino便利而把OS功能永久锁死。

Brookesia现成screenFlow只管理同一文档内屏幕切换，**不提供完整的跨文档路径返回栈**；后者仍由Notes导航服务补齐。
其事件默认错误继续等行为不直接成为本OS策略，需要适配到可配置的动作失败/传播规则。
LVGL核心与官方XML/编辑器工具链是不同许可范围；官方XML工具链不作为我们的公开格式依赖。已有完全开源JSON路径，没必要为此引入受限工具格式。

本地渲染与物理呈现分开：一次UI渲染可以有多次条带flush，不能每个flush就触发一次电子纸刷新。完成一帧后才提交给呈现驱动并等待其ready流程。
LVGL的flush-ready表示缓冲区可复用，不自动等于墨水已经显色完成。LCD/OLED可使用不同的呈现后端，上层UI保持一致。
UI是否在display busy期间改模型、接收事件或渲染下一帧由策略决定；驱动不接受新屏幕命令的约束始终生效。
JPEG/PNG/SVG等能力通过渲染后端发现；支持的本地子集可离线渲染，复杂内容可交浏览器/Hub编译。不能把所有格式都强制绑定网络，也不能承诺未实现的本地解码。

## 11. 字体、资源与导航

系统Flash包含基础字体、常用字号、默认UI和图标。SD提供扩展字体、字形覆盖、字号及资源包，通过统一字体资源接口注册，字体路径可相对引用。
预栅格化字体公布可用字号；TTF/OTF等矢量字体在支持的后端可按字号渲染，并受字形缓存/CPU预算约束。不能把“字号不在内置表中”作为OS永久限制。
LVGL有二进制字体文件装载和自定义glyph后端，但**从文件装载不自动等于按需读取全部字形**；大中文字库须采用经验证的分页/glyph缓存后端，不能完整吃进RAM。
缺字回退、字号替代或请求外部生成均为策略；默认字体质量沿用产品验收要求，不靠直接放大低分辨率bitmap充数。

公开VFS中系统与用户资源有稳定路径，底层卷可替换。导航地址包含文件路径、结构化query和anchor；query不进入真实文件名。
相对引用按文档目录解析并规范化，应用资源边界明确；跨文档/共享资源通过可发现的挂载点引用。
导航机制提供push/replace/back/refresh/reload、稳定entry_id与小状态保存；是否使用新版本、恢复哪些状态、刷新是否重跑进入动作由策略配置。
普通refresh可以选择保留返回栈和兼容状态；无需把“重画当前UI”实现成新入栈。副作用动作有独立身份与执行状态，不能由于页面重画不小心执行两次。
异步结果投递到指定entry/session；页面离开后的接收、取消、后台保存或跳转由配置决定，不能硬编码丢弃或抢回前台。

## 12. 公开发行边界

公开发行只包含系统、已支持驱动、公共API/Skill、默认资源和复现构建所需内容。用户能自行修改源代码和实现驱动。
内部试验入口、私有调试协议、波形探索工具、逆向记录、采集数据、对照图片与工作区临时文件，不作为隐藏开关或附加工具混入发行。
发行使用显式文件清单和依赖闭包；不能打包整个工作区再靠文件名黑名单排除。正式驱动有必要的内部实现，但不带操作者试验命令。
服务健康/资源指标属于产品运行能力，应保留；内部实验诊断工具与此不同。

## 13. 实施与验收门槛

1. 将现有原型与公开发行的源文件/依赖清单分开；公开资料不引导调用内部研究入口。
2. 建立可移植资源描述、配置事务、状态/预算与事件机制；将现有常量分成硬约束、构建容量、默认策略。
3. 实现统一设备ready门控、SPI事务调度与电源租约；验证屏幕BUSY期间仅SD在使用SPI、屏幕没有收到命令。
4. 集成双格式存储VFS、HTTP以及NFSv3移植验证；录音多sink与索引包读取共用这套服务。
5. 用Brookesia/LVGL最小集合验证无PSRAM配置、SD扩展字体和多显示后端；满足预算后才冻结公共UI格式与版本。
6. 测试两个不同BSP/显示后端、一个/三个按钮、无卡/有卡、不同网络接口适配，以及同一应用跨设备配置变化。

策略验收至少覆盖：刷新中忽略按钮与刷新中立即响应两种配置；FIFO与latest；按住/切换/定时录音；有限/无用户时限；RAM/SD/网络sink；满卡处理；关闭NFS；改字号后使用云端索引；未知CPU统计；配置延迟生效与冲突回退。
硬约束验收：任何策略都不能绕过BUSY、资源所有权和真实容量；超时不能自动把屏幕当ready。已完成的主机测试不替代新板上的物理/并发验收。
