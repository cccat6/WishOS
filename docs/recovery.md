# 操作完成与恢复

WishOS 按请求、应用实例和设备启动身份跟踪异步工作。网络送达、执行、安装、激活和显示完成各自有回执，调用方据此推进下一步。

## 常见情况

| 情况 | 系统行为 | 应用处理 |
| --- | --- | --- |
| 网络断开或服务器无响应 | 保留任务身份，按期限结束等待；连接恢复后协调已有回执 | 显示离线/失败状态，提供重试入口 |
| 结果已执行、确认丢失 | 按已有请求记录核对完成状态 | 继续确认，避免重复产生外部副作用 |
| 应用包未传完 | 候选文件与活跃版本分离 | 继续分块传输或放弃候选 |
| 预检失败、版本过期 | 保留当前应用及已安装版本 | 展示原因并准备新候选 |
| 内存或存储空间不足 | 拒绝本次准入，释放本次资源 | 提示释放空间、关闭资源或调整应用 |
| 应用运行错误 | 结束该实例，保留独立的 Home/语音与管理入口 | 返回桌面或修复应用后重新打开 |
| LCD 首帧失败 | 背光等待完整有效帧 | 默认桌面跳过失败的装饰启动页，继续加载正常页面 |
| 电子纸 BUSY / LCD DMA 工作中 | 等待原生安全完成边界 | 依配置处理输入与排队更新 |

## 版本与文件

应用更新以完整文件为单位写入新的修订目录，预检整个结果包，再提交目录与激活。旧版和新版使用各自身份；旧请求的回调仍交给对应的实例或系统任务处理。代码和资源恢复与用户数据、外部服务操作分别管理。

初始应用和字体存放在文件系统中。固件更新保留已有文件卷；改变分区布局时执行明确的数据迁移。

## 验证

`tools/test_wishos.sh` 覆盖请求身份、事件分页、并发、过期版本、OOM、文件租约、PNG缓存不足、首帧失败和应用退出清理等路径。两台首批设备的实际验证范围见[设备支持](supported-devices.md)。新适配器应同时验证成功路径与释放/恢复路径。
