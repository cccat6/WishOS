# WishOS 输入与界面规范

这份规范区分硬件事实、系统保留入口和普通应用的默认交互。设备维护者提供输入描述、
逻辑角色、时间参数与初始套装；运行时应用可以替换页面和普通操作绑定。所有方案都从
设备实际能力出发，不把触屏、快速连击、方向键或特定 GPIO 当作共同前提。

## 1. 负责层

- 驱动发布逻辑输入身份、事件、采样/去抖/长按/连击等实际合同。可保持电平的按钮、
  只报告一次触发的按钮、绝对位置滑条和增量编码器是不同能力。
- 系统负责原生输入采集、调度和呈现身份，以及独立可达的 Home/Voice 路由。可检测
  按住的语音键，在任何前台应用中长按进入语音、松开结束；前台通过
  `ai.voice_input(begin,end)`声明接管时交给该实例，否则进入默认语音应用。
  UI 失败或应用失去调度不会把受保护入口交给普通手势解释器。
- 普通 `navigation.lua`、套装和用户应用负责焦点顺序、确认、返回、菜单及操作含义。
  默认套装与用户程序使用同一接口，触屏与按钮调用相同的应用动作。
- Hub/Skill 根据设备合同生成包、帮助和预检；界面需要连同输入意义、反馈、返回路线
  一起交付。硬件描述不决定某个页面要显示哪些内容。

## 2. 默认交互配置

| 可用输入 | 移动 | 确认 | 返回上一层 | 系统 Home | 语音 |
|---|---|---|---|---|---|
| 一键，可连击 | 单击下一个焦点，循环 | 双击当前焦点 | 页面中可选的返回操作 | 默认三击 | 按住语音键，松开发送 |
| 一键，仅单击 | 依配置周期自动轮巡焦点 | 单击当前焦点 | 轮巡中包含返回 | 设备包声明的独立恢复绑定；菜单中也有 Home | 能检测保持电平时长按；离散触发输入提供显式语音操作 |
| 两键 | 导航键单击下一个 | 确认键单击 | 可选返回；支持连击时可配置确认键双击 | 保留系统绑定 | 指定语音键长按 |
| 三键 | 前一项、后一项 | 确认键 | 可选返回；支持连击时可配置确认键双击 | 保留系统绑定 | 指定语音键长按 |
| 更多按钮 | 按设备包的方向/前后/快捷角色 | 独立确认 | 可有独立返回 | 独立键或受保护手势 | 指定语音键长按 |
| 有触屏 | 保留上述非触屏路径，并提供直接点选 | 点选相同动作 | 可见返回目标 | 原生绑定保持可达 | 可额外提供按住说话控件 |
| 滑条/旋钮 | 正负方向映射下一项/上一项；绝对位置按阈值/滞回产生步进 | 使用按钮或明确的独立激活能力 | 正常可选操作 | 保留系统绑定 | 不推断滑动等同语音 |

方向角色使用已呈现控件的几何关系移动焦点，顺序角色按阅读顺序移动；应用也可自己实现导航。
角色绑定到设备声明的逻辑名称。三键示例不是规定所有 C6 或所有三键硬件的排列。
快速多击并非基本硬件前提：设备包可以扩大允许的时间窗口，或选择扫描模式。对只有
离散脉冲的输入，驱动明确发布该事实，应用不等待不存在的 release/hold。
原生恢复绑定可以采用可识别的慢速脉冲序列、独立输入或管理通道；扫描界面包含
Home/返回，与独立恢复入口共同验收。

扫描周期、去抖、连击间隔、长按阈值、滑条步长分别配置。自动轮巡只移动焦点；确认才
执行动作。电子纸的轮巡周期考虑实际完成时间，页面变化期间按配置的输入政策处理。
耗时或危险操作提供普通应用的确认页，不以停顿时长自动提交操作。

双击确认等待驱动给出完整的 click count。第一击先移动再用第二击确认会改变目标，
默认套装避免这种操作。三击交给系统 Home，不同时当作普通应用的返回或确认。
被系统占用的长按不会再产生普通短击操作。多键可补快捷键，但所有必要操作保留基本路线。

同类设计可参考 [AirPods 的分次按压与长按控制](https://support.apple.com/en-gb/guide/airpods/devb2c431317/web)
以及 [Apple 单开关自动扫描](https://support.apple.com/en-ie/guide/iphone/iph400b2f114/ios)。
这里采用的是适合 WishOS 的可配置默认规范，保留应用的普通输入自由度。

## 3. 普通导航模块

`notes.require('/system/lib/navigation.lua').bind(options)` 接收普通应用动作表。
`call/view/accept/actions/timer/cancel/back`由应用提供，`config.roles`按逻辑按钮名称
指定 click count 对应的 `next/previous/left/right/up/down/activate/back`，`config.mode`可选 `direct/scan`。
`config.last`可把返回等次级操作放到主要操作之后；这是应用配置，控件仍可正常选择。
省略 mode 时，单个只配置一次点击的按钮选择 scan，其余选择 direct。配置的点击上限
与真实硬件是否容易连击分别由驱动描述和设备包选择说明，不从软件上限推测电气性能。

焦点目标来自只读 `/sys/ui elements {view_id,cursor,limit}` 的已呈现几何，按页读取。
返回 `view_id/revision/activation/rotation/elements/cursor/more`；每项包括
`id,target,x,y,width,height`。坐标是逻辑界面的完成帧坐标。只有应用动作表中的可见目标
参与普通导航，几何本身不定义动作意义。页面替换后重新确认身份；新焦点尚未完成显示时
不会激活一个用户尚未看到的焦点。隐藏、失效或其它应用的目标均不执行。

`axis(source,event,options,callback)`消费由适配器声明的 `position`（归一化绝对位置）
或有符号 `delta`；`phase`可为 `begin/update/end/cancel`。`options.step`是应用步长。
滑动发生在何种硬件、其采样率与分辨率，仍由该驱动说明。此处只验证运行时合成事件，
当前两台 S3 没有据此宣称已实测独立触摸滑条。

## 4. 对齐与对比度

LVGL 已支持容器与 Flex 对齐；原问题主要来自页面定义的度量混用。文字行框包含
字体上/下留白，图标也可能带透明边。把二者外框居中，不能保证墨迹看起来居中。
另外，固定高度 label 的文字默认从顶部绘制，横向 textAlign 不负责纵向居中。

采用以下可复用规则：

1. 同级操作共用高度、字号、图标尺寸、图文间距和视觉权重。父容器用 Flex 的
   `mainAlign/crossAlign:center`居中整个图文组，子元素宽高使用 content。
2. 单行控件用 `metrics:ink`消除字体不对称留白。固定高度字段可显式设置
   `labelProps.verticalAlign:start|center|end`；必须是 label、ink、正整数固定 height。
   多行正文使用 line 度量和行距。省略新字段保留已有默认。
   `minFontSize`可为固定宽度ink单行标签声明字号下限，style.fontSize或继承值是上限；
   渲染器按真实字体宽度选择范围内字号。到达下限仍超出时遵守ellipsis/clip，不无限缩小。
   SSID等完整信息另保留可查看的来源，不把固定小字当作适配。
3. 先确定标题栏、内容区和操作栏的区域，再确定文本与图标槽。当前 320×240 套装
   使用统一的 4px 间距节奏、主要边距 12px、常规按钮 44px 高；这是此设备套装的选择，
   屏幕尺寸和触控精度不同的设备可以换一套尺寸。
4. 采用深色主文字、清楚的次级文字和足够明显的焦点轮廓。底色、图标或低对比色不能
   独自传递状态；文字/形状与颜色配合使用。当前 LCD 套装普通文字以至少 4.5:1作为
   数字颜色验收基线，并给低质 LCD 的小字号留更大余量。
5. 文字与图标归入实际承载它们的卡片／按钮，按父容器局部坐标布局；检查字形、二维码及多行末行均留在底图和内容区内。多行总高度依据真实字体行框与行距测量，不能直接用字号乘行数。操作栏与提示栏分开，检查中英文和长名称。
6. 图标保持宽高比，用相同的素材视口和槽尺寸；图片的 contain/cover 与裁剪选择独立。
   品牌 logo 与普通操作图标各用自己的用途，不把 logo 放进所有内容页。

参考 [LVGL 9.3 Flex](https://lvgl.io/docs/open/9.3/details/common-widget-features/layouts/flex)
与 [W3C 对比度说明](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum)。
颜色数值通过只能证明数字图像对比，实屏的视角、反光和光学效果仍需要实物检查。

操作说明采用完整动词，并按“单击 → 双击 → 三击 → 长按”排列。空间不足时分行或分到帮助页，保持字号与可读性。页面可只说明当前需要的手势；完整说明与实际配置一致。

## 5. 每次应用交付检查

- 完整发现输入数量、各自支持的事件/时序、触屏/轴输入、显示尺寸与完成模型。
- 按设备角色提供不用触屏的必要操作、可见焦点、返回/Home与简明帮助。
- 检查单/双/三击消歧、长按保留、提前松手、正在加载时的输入、过期页面身份。
- 检查一键与多键、扫描模式、轴输入变化、隐藏目标、界面替换与资源释放。
- 用同一渲染器生成中英文、短/长文字、空状态及选中状态的截图；检查纵横边界、
  图文组中心、字形中心、按钮之间的间距、裁剪、缩放、对比度和覆盖关系。
- 区分主机合成输入、目标编译、设备逻辑输入和真人按键/触摸/视觉验收；分别保留证据。

## LCD 启动呈现

背光与控制器初始化、完整帧写入分别由原生显示/背光驱动协调。LCD 控制器可接收数据时，背光继续保持关闭；首个完整帧的最后 DMA 完成后，才按继承的亮度开启。失败首帧保持关闭，下一次成功显示仍可正常开启。

当前两套 S3 的普通 Launcher 使用 `/dev/display` 的 `content_valid` 事实选择首次启动页。大 Logo、底色与 `boot_logo_ms` 均属于可替换的普通运行时资源；400ms 停留从显示完成开始计时，计时不会阻塞输入/网络。已有有效画面时直接打开正常页面，返回桌面不重放启动页。其它显示/设备使用各自应用配置，系统内核没有 Logo 或专用启动页面。
